# Установка Discord Social Bot на Altare / Pterodactyl

[← Русский README](README.ru.md) · [Создание и приглашение бота](docs/DISCORD_SETUP_RU.md) · [Типичные ошибки](docs/TROUBLESHOOTING_RU.md)

Инструкция для хостингов, использующих панель управления Python-ботами (Altare / Pterodactyl), когда **нет SSH, root-доступа и systemd**. Конкретные названия пунктов интерфейса могут различаться в зависимости от тарифа и шаблона.

> Для обычного Ubuntu VPS с SSH и отдельной службой смотри [docs/VPS_RU.md](docs/VPS_RU.md). **Не применяй команды `sudo` и systemd в консоли контейнера Altare.**

## 1. Создай и пригласи бота

1. В [Discord Developer Portal](https://discord.com/developers/applications) создай приложение и получи токен во вкладке **Bot**.
2. Включи **Message Content Intent**.
3. Пригласи бота на сервер со scopes **`bot`** и **`applications.commands`**.
4. Для базовой работы нужны View Channels, Send Messages, Attach Files, Embed Links и Read Message History. Для `webhook` — Manage Webhooks, для удаления исходного сообщения — Manage Messages.

Полная инструкция: [docs/DISCORD_SETUP_RU.md](docs/DISCORD_SETUP_RU.md).

## 2. Загрузи файлы из GitHub

1. Открой [репозиторий Discord-Social-Bot](https://github.com/Vetal12350/Discord-Social-Bot).
2. Выбери **Code → Download ZIP** на GitHub. Сохранится ZIP со всем публичным кодом.
3. Останови старый экземпляр бота в Altare, если он запущен.
4. В панели Altare открой **Files / File Manager**, загрузи ZIP и используй **Unarchive / Extract**, если панель это поддерживает.
5. Перемести **содержимое распакованной папки** в корень контейнера, если панель создала вложенный каталог. В корне должны находиться файлы `bot.py`, `config.py`, `requirements.txt`, `check_runtime.py` и остальные модули, а не дополнительная папка `Discord-Social-Bot-main/`.

Если в панели недоступна распаковка ZIP, распакуй архив на компьютере и загрузи содержимое через файловый менеджер/другой поддерживаемый хостингом способ. Не загружай в публичный репозиторий свой `.env`.

## 3. Выбери Python и установи зависимости

В **Startup** или настройках контейнера укажи:

- Python **3.13 или 3.14** (если доступны). Python 3.12 также проверялся на Ubuntu VPS, но предпочтительнее выбрать современный поддерживаемый образ.
- Главный файл **`bot.py`**; если шаблон использует переменную, она обычно называется `PY_FILE=bot.py`.
- Файл зависимостей **`requirements.txt`**; если поддерживается, `REQUIREMENTS_FILE=requirements.txt`.

В типичном Python-шаблоне зависимости устанавливаются автоматически перед запуском. Проверь в консоли, что `pip install -r requirements.txt` не завершился ошибкой.

Если хостинг даёт **настоящую shell-консоль**, можно установить пакеты вручную:

```bash
python -m pip install --user --no-cache-dir -r requirements.txt
```

Не используй `--user`, если активировано виртуальное окружение Python: в этом случае устанавливай пакеты в его окружение. Не вставляй эти команды в поле ввода запущенного Python-процесса — оно может не быть shell.

## 4. Настрой токен и режим работы

Самый безопасный способ — приватные переменные среды в Startup/Environment, если хостинг их поддерживает:

```dotenv
DISCORD_TOKEN=PASTE_YOUR_TOKEN_HERE
REPOST_MODE=webhook
TRANSLATE_ENABLED=true
```

Либо скопируй `.env.example` в `.env` **в корне рядом с `bot.py`** и заполни те же переменные. Убедись, что панель не делает файл публичным.

Дополнительно можно использовать:

- `ALLOWED_CHANNEL_IDS=` — пусто означает все доступные каналы; иначе перечисли ID через запятую.
- `TEST_GUILD_ID=` — ID сервера для ускоренной синхронизации `/video`.
- `MYMEMORY_EMAIL=` — необязательная почта для квоты внешнего переводчика.

**Никому не передавай токен.** Не публикуй `.env`, не отправляй его в чат, не включай в ZIP для других людей. Если в контейнере уже задана переменная среды, она имеет приоритет над `.env`.

## 5. Проверка FFmpeg / GIF

Для преобразования анимации нужны **`ffmpeg` и `ffprobe`**, желательно с `libwebp_anim` или GIF-энкодером. На хостингах они могут отсутствовать и не всегда могут быть установлены самим пользователем.

Временно укажи в Startup главный файл **`check_runtime.py`**, запусти его один раз и посмотри результаты. Проверка **не подключается к Discord и не читает токен**. Ожидаемые строки:

```text
Bot imports and Pillow WebP: OK
GIF preflight: OK
```

После проверки **верни главный файл `bot.py`**. Завершение проверочного процесса — нормально.

Если FFmpeg не найден, попроси поддержку хостинга предоставить образ с FFmpeg/FFprobe или используй VPS. Обычные изображения и совместимые MP4 могут обрабатываться отдельно от анимаций.

## 6. Запуск и тестирование

Убедись, что **другой экземпляр Discord Social Bot с тем же токеном не запущен** (в том числе на локальном ПК или другом VPS).

В Startup установи `bot.py`, нажми **Start**, посмотри консоль. Ожидай `Connected to Discord`. Если `Slash commands synced` не появилось, проверь scopes, настройки сервера и журнал.

В приватном Discord-канале попробуй:

1. Публичную публикацию X/Twitter с фото или видео.
2. Публикацию X с GIF — изображение должно анимироваться, если FFmpeg настроен и источник доступен.
3. Публичную публикацию TikTok.
4. Одиночную ссылку — в режиме `webhook` исходное сообщение может удалиться после подтверждения репоста.
5. Сообщение с комментарием и ссылкой — исходный текст должен **сохраниться**.
6. Команду `/video`.

Не все медиа доступны через сторонние сайты. При ошибках сохранение исходной ссылки — ожидаемый безопасный вариант.

## 7. Обновление

1. Сохрани приватную конфигурацию `.env` **отдельно** и не включай её в публичные архивы.
2. Останови бота.
3. Скачай свежий ZIP из GitHub и замени **только файлы проекта**, не трогая приватный `.env`.
4. Установи обновлённые зависимости (если изменился `requirements.txt`) и повтори `check_runtime.py`.
5. Запусти `bot.py` и проверь тестовый канал.

При ошибках смотри [раздел диагностики](docs/TROUBLESHOOTING_RU.md). Для отката заранее сохраняй предыдущую версию кода и перечень зависимостей, но **никогда не публикуй файл с токеном**.
