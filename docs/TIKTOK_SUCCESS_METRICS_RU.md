# Измерение фактической успешности TikTok

Раньше repost_attempt появлялся только после inflight admission. Пятая
одновременная ссылка пользователя могла быть отклонена, не попав в этот
denominator. Из-за этого receipt/attempt завышает видимую общую успешность.

Этот PR добавляет только tiktok_received перед проверками inflight/pressure,
после фильтров ботов, разрешённых каналов, повторных message_id и прав Send.
Никаких очередей, повторов, отправок, изменения лимитов или X-поведения нет.
В production отказов inflight не обнаружено; это устранение пробела измерения,
а не заявление о причине конкретного инцидента.

Строка содержит только message_id, channel_id и список безопасных source_keys.
Источник не содержит текста поста, автора, handle, query, CDN URL или токена.
Не более трёх уже распознанных источников в сообщении; X в список не включается.

Собирать по уникальной паре (message_id, source_key):

1. tiktok_received — допустимые входы в настроенных каналах с правом Send.
2. repost_attempt — допущены к обработке; разность и repost skipped показывают
   потери admission. Один message_id может содержать несколько ссылок.
3. repost_receipt media_confirmed=True — Discord подтвердил ожидаемые файлы и текст.
4. Отдельно считать неуспешные stage/HTTP/guard, неизвестные исходы и
   успешные отправки после media_worker_retry. Retry не является новой пересылкой.
5. Скользящие окна 24 часа/7 дней, число различных постов и размер выборки.
   Не смешивать старые версии и каналы с разными настройками.

Показатели: confirmed/received и confirmed/admitted. Отдельно доля пропусков,
unknown, ошибки по стадиям, latency, число дубликатов, ручная приёмка плеера/звука.
Receipt не доказывает полное сохранение исходного поста или воспроизведение;
Photo Mode без перенесённой музыки сохраняет исходник.

Если получен вход без terminal outcome к концу максимального бюджета, считать
unknown, а не success. Отказ по inflight не отмечает seen_messages и не
публикует новое уведомление. Исторические входы, раньше не логировавшиеся,
задним числом восстановить нельзя.

PR независим от bounded TikTok GET retry; изменения затрагивают разные пути.
После отдельного разрешения выпускать canary с keep_all, без самостоятельных
Discord-сообщений агента. Ограниченную очередь с TTL/backpressure рассматривать
отдельно, если новая метрика подтвердит существенные потери admission.
