## Изменение в этом PR

Исправляется подтверждённый пробел диагностики, **не заявляется исправление
неизвестной причины отказа**:

- Parent guards пишут отдельные причины memory_pressure, directory_limit,
  stdout_limit, stderr_limit, rss_limit, cpu_limit, wall_timeout.
- Записываются измеренные размеры, время, RSS/CPU и действующие лимиты;
  для завершившегося worker — код выхода и безопасная категория ошибки.
- События имеют безопасный source_key (числовой ID или shortcode без
  handle/query/CDN URL), а вход и отказ — message_id и channel_id.
- Prepare разделён в журнале на webhook_acquire, video_prepare,
  animation_convert, image_prepare. Сетевые операции и их порядок не менялись.
- Сохранены типы исключений, лимиты, semaphore, уничтожение child и cleanup.
  Поведение переводов, Webhook, GIF и безопасного удаления не менялось.

108 unittest и Ruff проходят на Windows и в изолированной Linux-копии VPS.
Новые тесты различают родительские guards, проверяют cleanup, таймаут,
безопасность логов и запрет отправки/удаления при отказе третьего ролика.
Ресурсные отказы в этих тестах смоделированы, а не названы live-причиной.

## Ограниченный повтор HTTP

HTTP 403/429 в этом инциденте не подтверждён, поэтому автоматический повтор
не добавлен. После подтверждения конкретного HTTP-этапа допустимо отдельно
рассмотреть один повтор подготовки/GET с короткой ограниченной задержкой,
только в общем бюджете времени/диска/CPU, с cleanup частичного файла и
соблюдением Retry-After (если задержка не помещается в бюджет — отказ).
Нельзя менять IP, подменять cookies, обходить challenge или повторять
неоднозначный Webhook POST. Слепой повтор сейчас мог бы скрыть ресурсную
ошибку и увеличить нагрузку без доказанного исправления.

Следующий шаг — отдельно согласовать выпуск диагностического изменения и
повтор одной ссылки пользователем. До этого production остаётся на 94ca0843.
