# Проверка TikTok перед выпуском

Автоматические тесты не подключаются к Discord и не используют токены:

```bash
python -m unittest discover -s tests -v
ruff check .
python -m compileall -q .
python -c 'import animation, media, bot, config, social_posts, webhook_repost'
```

`tests/test_repost_integration.py` проверяет полный путь пересылки с реальными
парсерами, временными файлами, проверкой MP4, сборкой multipart и обработкой
подтверждения webhook. Внешние сервисы и Discord HTTP заменены тестовыми
ответами. MP4-образцы моделируют проверяемые контейнерные структуры и не
предназначены для проверки воспроизведения. Тесты охватывают меньший вариант
видео, три слайда по порядку, оригинал и перевод, четыре быстрых сообщения,
имя/аватар отправителя, запрет упоминаний и сохранение исходника при ошибках.

Удаление требует подтверждённого webhook с теми же файлами и текстом,
проверки канала/webhook ID, полной подписи и медиа, прав и повторного чтения
исходного сообщения. Ошибка запрошенного перевода блокирует удаление.
TikTok-видео без полученной аудиодорожки сохраняет исходник, даже если
беззвучный MP4 удалось отправить. Photo Mode всегда сохраняет исходник,
пока его звук не переносится. `keep_link` сохраняет URL, а `keep_all`
не изменяет исходник.

## План проверки в Discord

Этот план сам по себе не разрешает merge, deploy, изменение конфигурации
или перезапуск. При запрете обновления работающий бот проверяет только
уже развёрнутую версию, поэтому его результаты нельзя приписывать кандидату.

1. Если настроен отдельный тестовый бот, использовать его собственный токен
   и приватный тестовый сервер/канал. Не запускать второй процесс с токеном
   рабочего бота. Не копировать токены в команды, отчёт или журнал.
2. Если тестового бота нет, подготовить приватный канал рабочего бота,
   доступный только участнику тестирования и боту. Проверить существующий
   allowlist каналов, View Channel, Send Messages, Read Message History,
   Embed Links, Attach Files, Manage Webhooks и Manage Messages.
   Сейчас настройки не менять. Добавление канала и загрузка кандидата
   выполняются только в будущем согласованном окне обновления.
3. Перед таким окном снова проверить GitHub main, точный SHA кандидата,
   `git status` и HEAD в `/opt/discord-social-bot/app`. Сохранить уникальные
   серверные изменения, резервную копию кода и приватной конфигурации с
   прежними правами. Не выполнять reset/clean поверх серверных файлов.
4. Для будущего canary ограничить обработку приватным каналом и начать с
   `SOURCE_MESSAGE_ACTION=keep_all`. Зафиксировать прежние настройки для
   восстановления. Должен работать ровно один экземпляр рабочего бота;
   загрузка нового кода требует контролируемого перезапуска только
   `discord-social-bot.service`. FunPayFlow и другие службы не трогать.
5. Отправить по одной публичной ссылке: обычное видео со звуком; ролик с
   несколькими вариантами размера; Photo Mode с 2–10 слайдами; пост с
   английским текстом, хэштегом и упоминанием. Проверить воспроизведение и
   звук, порядок всех слайдов, неизменность оригинальной подписи, перевод,
   отображаемое имя и аватар автора сообщения с суффиксом Social Bot.
6. Быстро отправить четыре **разные** ссылки одним автором в четырёх
   сообщениях. Проверить четыре пересылки, отсутствие дубликатов и
   восстановление счётчиков после обработки. Повтор одной ссылки во время
   активной загрузки намеренно обрабатывается иначе.
7. Отдельным согласованным переключением включить `delete` для проверки
   необратимого действия. Начинать только после успешного `keep_all`.
   Удаляться может лишь одно сообщение с единственной ссылкой без
   комментария, вложений, ответа, стикеров или опроса. Перед удалением
   требуется `webhook_confirmation reason=confirmed` и повторное чтение
   неизменённого сообщения. Подпись не должна быть обрезана; перевод,
   если он требовался, должен быть получен. Photo Mode не удаляется.
8. В приватном канале проверить сохранение исходника при недоступном
   публичном посте и временном отсутствии Attach Files. Вернуть права
   сразу после проверки. Не блокировать сеть VPS и не создавать сбои
   общих служб. Таймауты, 403/429/5xx, неполные webhook-ответы, потеря
   звука/перевода и изменение сообщения покрываются автоматическими
   тестами; это не выдаётся за live-сбой Discord.
9. При неожиданном удалении, потере медиа или дублировании приостановить
   canary и выполнить подготовленный откат только этого бота. При
   неоднозначном таймауте POST или DELETE сначала вручную проверить канал:
   удалённое действие могло завершиться на Discord. Не повторять POST
   вслепую. После успеха восстановить allowlist и согласованные настройки
   источника; расширять обработку постепенно.

Критерий завершения live-проверки: воспроизведение видео со звуком,
полнота галереи и текста, четыре сообщения без потерь и дубликатов,
подтверждённое безопасное удаление и сохранение исходников в отрицательных
сценариях. Одна успешная публичная ссылка не доказывает доступность всех
постов TikTok, регионов или CDN.
